Chapter 3

The Cost: What You're Actually Storing

Every token retains Key and Value activations in GPU memory. As context length and batch size scale, KV cache footprint rapidly rivals model parameter weights.

⚡ The Memory Explosion: Working KV cache memory scales strictly linearly with context length T and batch size B (M = 2 · B · L · H · D · s · T), rapidly outstripping high-bandwidth GPU memory.
64.4 GB Cache for 128k on Llama-70B

Architectural Evolution: Reducing KV Footprint

MHA · Multi-Head Attention
nKV = nQ

Independent K/V head per query head. Maximum memory footprint (e.g. GPT-3 175B with 96 KV heads).

GQA · Grouped-Query Attention
nKV < nQ

Multiple query heads share each KV head (e.g. Llama-3 with 32 Q heads sharing 8 KV heads). Cuts cache size 4× to 8×.

MLA · Multi-Head Latent Attention
ctKV ∈ ℝ⁵¹² + ktR ∈ ℝ⁶⁴

Compresses KV into a shared 512D latent vector + 64D decoupled RoPE key (576 elements total per layer).

Governing KV Cache Formulas

Conventional MHA / GQA Pope et al. 2023
VRAMKV = 2 × L × nKV × dhead × T × B × s

Factor of 2 accounts for separate Key and Value tensors.

DeepSeek-V2 MLA DeepSeek-AI 2024
VRAMMLA = L × (dc + dr) × T × B × s

Low-rank latent dc = 512 + RoPE dr = 64 (576 elements/layer). No factor of 2.

Chapter 4

Limitations in Production: Prefill vs. Decode

Inference splits into two opposite hardware regimes: parallel compute-bound prefill vs. memory-bandwidth-bound decode.

⚡ The Hardware Ceiling: Decode step execution is strictly memory-bandwidth bound with arithmetic intensity < 10 FLOP/byte, leaving >90% of GPU tensor cores idle while reading KV cache memory from HBM.
153.0 FLOP/byte Memory Knee (A100)

Phase 1: Prefill

Compute-Bound
Matrix-Matrix (GEMM) · Highly Parallel

Processes the entire prompt simultaneously across thousands of GPU Tensor Cores.

  • Execution: All tokens in a single forward pass.
  • Intensity: High (I >> 150 FLOP/byte).
  • Bottleneck: Compute execution units; memory bus is not saturated.

Phase 2: Decode

Memory-Bound
Matrix-Vector (GEMV) · Sequential

Generates 1 token at a time, streaming the entire accumulated KV cache from HBM for each step.

  • Execution: Autoregressive loop, 1 token per sequence.
  • Intensity: Extremely low (I ≈ 0.99 – 4 FLOP/byte).
  • Bottleneck: Memory bandwidth; Tensor Cores wait for HBM data transfers.

Roofline Model: Hardware Ceilings

P = min(Ppeak, I × Bmem)

🔬 View Analytical Hardware Derivations & Roofline Equations

Decode Arithmetic Intensity: Idecode = FLOPs / Memory Traffic = (2 · P · B) / (2 · P + MKV).

Because model weights P (e.g. 70B = 140 GB FP16) must be streamed from HBM into on-chip cache for each single token step, memory traffic dominates. The GPU's memory bus quickly saturates while tensor cores sit mostly idle.

Hardware Knee Point: I* = Ppeak / Bmem = 312 TFLOPS / 2,039 GB/s = 153.0 FLOP/byte (NVIDIA A100 80GB SXM). Any operation with intensity below 153.0 cannot achieve peak FLOPS.

Taxonomy of State Semantics

01 · Explicit Token Addressable Buffers Standard KV, StreamingLLM: retains explicit activations.
02 · Compressed Token Addressable Latents DeepSeek MLA: low-rank vectors indexed per token.

05 · Learned Graph Synaptic Plasticity Dragon Hatchling (BDH): Hebbian reweighting on fixed topology.

BDH does not make memory disappear. It changes what memory means.

A Transformer stores history as explicitly addressable token vectors. BDH stores history in an evolving synaptic state. The former preserves direct access to individual tokens at the cost of growing memory; the latter fixes state size but forces information to interact within shared synaptic connections.

“BDH is not simply a better KV cache. It is a different computational model for memory.”
