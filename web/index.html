Chapter 2

Naive Recompute vs. The Cache

During autoregressive generation, predicting each new token requires attending over all previous tokens in the sequence. Without caching, the model repeatedly recomputes the Key and Value projections for every historical token at every single generation step. KV caching stores these projections after their first computation, eliminating repeated projection work while attention continues to operate over the growing context.

Chapter 3

The Cost: What You're Actually Storing

Every token passed into an autoregressive model leaves behind Key and Value activations that must be retained in GPU memory. As sequence length and batch size scale, this cache expands until it rivals or dwarfs the parameter count of the model itself.

Architectural Evolution: Reducing the KV Footprint

Different attention architectures mitigate the memory cost of KV storage in fundamentally different ways:

MHA · Multi-Head Attention
nKV = nQ

Every query head has an independent key and value head. High expressiveness, but maximum memory footprint (e.g. GPT-3 175B with 96 KV heads).

GQA · Grouped-Query Attention
nKV < nQ

Multiple query heads share each key-value head (e.g. Llama-3-8B with 32 Q heads sharing 8 KV heads). Cuts KV cache size by the grouping ratio (4:1 or 8:1).

MLA · Multi-Head Latent Attention
ctKV ∈ ℝ⁵¹² + ktR ∈ ℝ⁶⁴

Replaces per-head K/V tensors with a low-rank compressed latent vector plus decoupled RoPE key (576 elements total per layer). Dramatically compresses cache without losing multi-head capacity.

Governing KV Cache Capacity Formulas

Conventional MHA / GQA (Llama-3, GPT-3) Pope et al. 2023
VRAMKV = 2 × L × nKV × dhead × T × B × s

The factor of 2 accounts for separate Key and Value tensors. L is decoder layers, nKV is KV head count, dhead is head dimension, T is context length, B is batch size, and s is bytes per element.

Attributed to Pope et al. 2023 (Efficiently Scaling Transformer Inference on TPU v4).
DeepSeek-V2 MLA (Low-Rank Latent Cache) DeepSeek-AI 2024
VRAMMLA = L × (dc + dr) × T × B × s

Compresses Keys and Values into a single shared latent vector dc = 512 plus decoupled RoPE key dr = 64 (total 576 elements per token per layer). No factor of 2 is applied.

Attributed to DeepSeek-AI 2024 (DeepSeek-V2 Technical Report).

Chapter 4

Limitations in Production: Prefill vs. Decode

A common misconception is that the KV cache is merely a capacity concern — an issue of having enough gigabytes on the GPU. In real production serving systems, the physical mechanics of KV cache retrieval dictate throughput and execution latency, bifurcating transformer inference into two radically different operating regimes.

Phase 1: Prefill

Compute-Bound
Matrix-Matrix (GEMM) · Highly Parallel

Processing the full input prompt at once. The model computes Key and Value projections for all prompt tokens in parallel across thousands of tensor cores.

  • Execution: Ingests all Tprompt tokens simultaneously in a single forward pass.
  • Arithmetic Intensity: High (Iprefill >> 150 FLOP/byte). High compute-to-memory ratio keeps GPU tensor cores saturated.
  • Hardware State: Tensor cores run near peak; memory bus is not the primary bottleneck.

Phase 2: Decode

Memory-Bandwidth-Bound
Matrix-Vector (GEMV) · Strictly Sequential

Generating one token at a time using the accumulated cache. For small batches, major layers behave approximately like matrix-vector operations; larger batches become matrix-matrix-like across the batch.

  • Execution: Autoregressive loop generating 1 token per step per sequence.
  • Arithmetic Intensity: Very low (Idecode ≈ 0.99 – 4 FLOP/byte). Each step must stream the entire KV cache from HBM just to generate a single token.
  • Hardware State: Tensor cores sit idle most of the cycle, waiting on memory transfers from High Bandwidth Memory (HBM).

Analytical Roofline Model: Hardware Bottlenecks

Attainable Performance P = min(Ppeak, I × Bmem) · Williams, Waterman, Patterson (2009)
A100 80GB SXM · 312 TFLOPS Dense FP16 · 2,039 GB/s HBM2e
● Foundational Methodology · Williams et al. 2009 (Roofline Model)

Williams, Waterman, and Patterson (2009) introduced the Roofline model to relate floating-point performance to memory bandwidth and arithmetic intensity. The knee point (I* = Ppeak / Bmem ≈ 153.0 FLOP/byte on the A100) demarcates memory-bandwidth-bound from compute-bound execution.

Systems Engineering Consequence: Prefill/Decode Disaggregation & PagedAttention

Because prefill and decode exhibit fundamentally opposite hardware bottlenecks — compute-bound matrix-matrix multiplication versus memory-bandwidth-bound streaming of the growing KV cache — co-scheduling them on the same GPU creates severe resource interference. Bursty prefill passes monopolize tensor cores, while decode steps stall waiting for memory bandwidth. To resolve this, modern production inference architectures physically separate the two phases:

vLLM (Kwon et al. 2023, PagedAttention): Introduces virtual memory paging for KV caches, eliminating fragmentation and near-doubling effective capacity without changing the underlying bandwidth requirements.

DistServe (Zhong et al. 2024): Formally disaggregates prefill and decode onto physically separate GPU pools or dedicated scheduling phases. By separating compute-heavy prompt ingestion from latency-critical token generation, DistServe eliminates "prefill interference" and head-of-line blocking, allowing each phase to be provisioned and optimized for its own hardware bottleneck.

Scientific Honesty & Methodology Notes
Roofline model: Analytical upper-bound model (Williams et al. 2009), not a direct measurement of A100 kernel performance. Actual measured performance can be lower due to kernel launch overhead, tensor core efficiency, cache hierarchy, synchronization, and communication.
Memory traffic: Idealized analytical estimate of effective weight read plus KV cache streaming (Mstep = 2P + B · ktoken · T); actual HBM traffic depends on kernel implementation and cache hierarchy.
Dense vs. Sparse compute: NVIDIA lists 624 TFLOPS FP16 for the A100 80GB SXM with structured sparsity; this chapter's roofline uses the 312 TFLOPS dense FP16 figure.
Per-request token rate: Simplified analytical approximation under synchronized batch-step assumptions; production asynchronous continuous-batching engines exhibit request-level latency variance.

Given these costs, researchers have tried several ways to avoid ever growing this cache in the first place.

Chapter 5

Alternate Memory Approaches, Compared Honestly

Faced with the quadratic compute of naive recomputation (Chapter 2) and the memory-bandwidth wall of unbounded KV caches (Chapters 3 & 4), the machine learning community has proposed diverse memory architectures. But memory reduction never comes for free: each approach trades away explicit token-addressability, recall precision, or softmax sharpness. Here, we compare these mechanisms under a common normalized analytical scale.

Normalized Analytical Comparison Notice
Except where explicitly stated, these numbers are normalized analytical estimates that place different memory mechanisms on a common 32-layer, FP16 comparison scale (L=32, dmodel=4096, dhead=128, s=2 bytes). They are not measurements of the original published model implementations, which differ in layer count, precision, and architectural hyperparameters.
These curves describe state-memory scaling, not model quality, latency, throughput, or recall accuracy. Two methods with identical memory growth can have radically different retrieval behavior.

Taxonomy of State Semantics: What Kind of Memory?

Before comparing numbers, we must distinguish what information physically survives inside each state representation:

01 · Explicit Token Token-Addressable Buffers Standard KV, StreamingLLM, H2O: stores explicit activations per position.
02 · Compressed Token Token-Addressable Latents DeepSeek MLA: low-rank compressed vectors still indexed per token position.
03 · Recurrent Associative Matrix Fast Weights Linear Attention: folds outer products into a fixed-size associative matrix.
04 · Dynamical Recurrent Continuous State Vectors Mamba / SSM: continuous-time hidden state evolving via selective recurrence.
05 · Learned Graph Dynamical Synaptic Graph Dragon Hatchling (BDH): Hebbian edge-reweighting on a fixed graph topology.

Standard KV-Cache

Explicit Token Memory
O(T) Linear
MKV(T) = 2 · L · nKV · dhead · s · T = 131,072 · T bytes
Information Retained: Full, uncompressed past Key & Value activation projections for every token.
Real Limitation: Unbounded linear growth in cache state memory; acute memory-bandwidth saturation during decode (Chapter 4).
Vaswani 2017 · Pope 2023

Attention Sinks & Eviction

Explicit Token Memory (Windowed)
O(1) Fixed Window
MStreaming(T) = 131,072 · min(T, 1028) bytes [Wsink=4, Wwin=1024]
Information Retained: Initial sink tokens + recent sliding window. Intermediate tokens evicted. (H2O uses dynamic heavy-hitter scoring).
Real Limitation: Once a token's KV state is evicted, this cache mechanism no longer has direct access to that token's stored K/V representation. Exact recovery is unavailable unless preserved elsewhere.
Xiao 2023 (StreamingLLM) · Zhang 2023 (H2O)

Low-Rank Compression (MLA)

Compressed Token Memory
O(T) Compressed
MMLA(T) = L · (dc + dR) · s · T = 36,864 · T bytes [L=32 normalized]
Information Retained: 512D compressed KV latent (ctKV) + 64D decoupled RoPE key (ktR). 576 elements/token/layer.
Real Limitation: Reduces footprint per token by 71.875% vs standard KV, but does NOT make memory constant in T. Unbounded linear growth remains at long contexts.
DeepSeek-AI 2024 (DeepSeek-V2)

Linear Attention (Fast Weights)

Recurrent Associative State
O(1) Matrix Memory
MLinear = L · nhead · r · dv · s = 33,554,432 bytes [r=dv=128]
Information Retained: Associative matrix accumulating outer products: St = St-1 + φ(kt) vtT.
Real Limitation: Replaces exact softmax attention with a kernelized/linearized mechanism, changing retrieval behavior and introducing capacity/interference trade-offs in its finite recurrent state.
Katharopoulos 2020 · Schlag 2021

State-Space Models (Mamba)

Dynamical Recurrent State
O(1) Vector State
MSSM = L · dmodel · dstate · s = 4,194,304 bytes [dstate=16, state-only]
Information Retained: Continuous-time hidden state evolving via input-dependent selective discretization: ht = Āt ht-1 + B̄t xt.
Real Limitation: Fixed-size recurrent state can make exact long-range retrieval and associative recall more difficult than explicit token-addressable memory; performance depends strongly on architecture, training, and task.
Gu & Dao 2023 (Mamba)

Dragon Hatchling (BDH)

Learned Graph Memory
O(1) Graph State
Fixed graph state; sequence-length-independent state footprint [See Chapter 6]
Information Retained: Synaptic edge connection weights and dynamic activations on a learned bipartite network graph.

The Fundamental Bargain of Attention vs. State

The KV cache solves a very specific problem: preserve token-addressable information so future queries can directly retrieve it. Every alternative changes that bargain. Eviction keeps only selected tokens. MLA compresses token information. Linear attention folds history into an associative state. SSMs compress history into a dynamical state. BDH explores a learned graph as memory. The interesting question is therefore not whether memory can be made smaller—it can—but what information is lost, compressed, or transformed when we do so.

Chapter 6 asks whether memory can be neither a growing token buffer nor a conventional recurrent vector, but a dynamically modified graph.
